# AI Assistant для STE Slicer

Плагин для STE Slicer 7.10 (Stereotech, форк Cura 3.6). Добавляет в слайсер чат с ИИ-агентом.
Вы описываете задачу печати текстом, прикладываете модель (STL/OBJ/3MF), фото (JPG/PNG) или ТЗ (.docx).
Агент через MCP-инструменты:

- выбирает режим печати: **3D** (`classic`), **5D** (`cylindrical_full`) или **5D Spiral** (`cylindrical`);
- подбирает материал по инженерным требованиям ТЗ, профиль и ключевые настройки;
- анализирует геометрию модели, ориентирует её и расставляет на столе;
- запускает слайсинг, сохраняет проект `.3mf` и G-code, проверяет G-code;
- объясняет каждое решение: «параметр → значение → почему».

Команда **HandBloodы**.

## Установка

1. Установите STE Slicer 7.10. Для 5D-режимов активируйте лицензию ATSS.
2. Скопируйте папку `AIAssistant` в папку плагинов пользователя:
   `%APPDATA%\steslicer\7.10\plugins\AIAssistant`
   (открыть папку конфигурации: **Справка → Показать папку конфигурации**).
3. Перезапустите STE Slicer. В меню появится пункт **AI Assistant**.

Сторонние Python-библиотеки не нужны: плагин использует только то, что уже есть в дистрибутиве
(Python 3.5, PyQt5, numpy).

## Настройка LLM (URL и ключ)

1. **AI Assistant → Настройки LLM**. В браузере откроется окно настроек.
2. Укажите **Base URL** (OpenAI-совместимый API, например `https://api.timeweb.ai/v1`),
   **API key** и **модель** (например `dashscope/qwen3.8-flash`).
3. Нажмите **Проверить связь**, затем **Сохранить**.

Ключ хранится в настройках STE Slicer (`steslicer.cfg`, раздел `ai_assistant`) и не попадает в исходный код.

HTTPS-сертификаты проверяются по хранилищу Windows, по `certifi` слайсера и по файлу `agent/certs/extra_roots.pem`.
В этом файле лежат публичные корневые сертификаты, которых нет в старом наборе слайсера (например, GlobalSign Root R46 для `api.timeweb.ai`).
Если ваш LLM-сервер подписан другим новым корнем, добавьте его PEM в этот файл.

## Использование

1. **AI Assistant → Открыть чат**. Чат откроется в системном браузере по адресу `http://127.0.0.1:8765/`.
2. Прикрепите файлы (кнопка «＋» или перетаскивание) и опишите задачу, например:
   *«Кронштейн под нагрузку, PETG, без поддержек»* или *«Подготовь проект по приложенному ТЗ»*.
3. В чате видно каждый вызов инструмента и его результат. Справа показаны состояние слайсера,
   прогресс слайсинга (время печати, расход материала) и пути к сохранённым файлам.
4. По умолчанию результаты сохраняются в `Документы\STE Slicer AI Results\<имя модели>\project.3mf` и `result.gcode`.
   Папку можно сменить в настройках.

## MCP-сервер

Плагин реализует MCP-сервер (JSON-RPC 2.0 поверх HTTP): `POST http://127.0.0.1:8765/mcp`.
Поддерживаются методы `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`.
Эти же инструменты агент передаёт в LLM как `tools`. Вызовы от внешних MCP-клиентов тоже отображаются в чате.

```bash
curl -s -X POST http://127.0.0.1:8765/mcp -H "Content-Type: application/json" -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/list\"}"
```

### Инструменты

| Группа | Инструменты |
|---|---|
| Настройки и профили | `get_scene_info`, `get_settings`, `find_settings`, `set_settings` (глобальные и экструдера), `reset_settings`, `list_profiles`, `set_profile`, `create_profile`, `set_print_mode` (3D ↔ 5D) |
| Материалы | `list_materials`, `set_material`, `recommend_materials` (подбор по требованиям ТЗ), `material_properties` |
| Модели | `load_model`, `list_objects`, `analyze_model`, `orient_model` (3D/5D), `transform_model` (перемещение, поворот, масштаб), `arrange_all`, `delete_objects` |
| Слайсинг | `slice` (ожидание результата: время, материал), `slice_status`, `export_gcode`, `save_project`, `validate_gcode` |

## Как агент принимает решения

- **Анализ геометрии** (`analyze_model`, numpy): габариты, объём, тело вращения и его ось (по круглым сечениям),
  осевое отверстие, площадь нависаний и контакта со столом, лучшая ориентация для 3D.
- **База материалов** (`agent/knowledge.py`): Tg/HDT, плотность, водопоглощение, модуль упругости, стойкость к УФ,
  маслам, щелочам, кислотам и спиртам, износостойкость, гибкость, ESD. Есть для всех материалов Stereotech из дистрибутива.
  `recommend_materials` фильтрует материалы по числовым требованиям ТЗ.
- **Правила печати**: когда нужен 5D (тела вращения, нагрузка по окружности, гладкая цилиндрическая поверхность),
  как выбирать диаметр основания и ориентацию, какие настройки нужны для прочности, точности и внешнего вида.
- **Проверки кодом**: значения вне `minimum_value`/`maximum_value` отклоняются, а выход за рекомендуемый диапазон
  возвращается как предупреждение. G-code проверяется: есть слои и экструзия, температура соответствует материалу.

## Архитектура

```
SPA (web/: index.html, app.js, style.css)
   │  HTTP: fetch + long polling /api/events
Python-плагин (AIAssistant.py: меню, HTTP-сервер, настройки)
   ├── agent/agent.py        — цикл диалога с LLM (OpenAI Chat Completions + tool calling, картинки как image_url)
   ├── agent/mcp_server.py   — MCP JSON-RPC: initialize, tools/list, tools/call
   ├── agent/tools.py        — реестр инструментов (общий для MCP и LLM)
   ├── agent/slicer_api.py   — API STE Slicer: сцена, стеки настроек, профили, бэкенды 3D/5D, писатели 3MF/G-code
   ├── agent/geometry.py     — анализ сетки (numpy)
   └── agent/knowledge.py    — база материалов, правила печати, системный промпт
```

Сцену, настройки и бэкенд трогаем только из главного потока Qt (`agent/main_thread.py`). Писатели 3MF и G-code,
наоборот, вызываются из рабочего потока: внутри они сами переходят в Qt-поток через `@call_on_qt_thread`.
Перед слайсингом плагин ждёт, пока бэкенд и проверка настроек (MachineErrorChecker) простоят без дела 2 с.
Иначе STE Slicer может упасть или зависнуть.

## Отладка

- Логи: `%APPDATA%\steslicer\7.10\steslicer.log` (строки `AIAssistant`).
- `GET http://127.0.0.1:8765/api/debug/threads` — стеки всех Python-потоков слайсера (работает, даже если интерфейс завис).
