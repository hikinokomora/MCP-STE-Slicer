# Как участвовать в разработке

Спасибо, что помогаете проекту. Ниже — правила, которые помогают держать репозиторий в порядке.

## Ветки

- `main` — рабочая версия. Напрямую в `main` не коммитим, изменения идут через pull request.
- `feature/<название>` — новая функция.
- `fix/<название>` — исправление ошибки.
- `docs/<название>` — документация и оформление.

## Коммиты

- Один коммит — один смысл. Маленькие коммиты легче читать и откатывать.
- Короткое название в повелительном наклонении: «Добавить клиент LLM», «Исправить расчёт нависаний».
- Служебных трейлеров и подписей инструментов в сообщениях не добавляем.

## Код

- **Совместимость с Python 3.5.** Слайсер работает на нём. Не используйте f-строки, аннотации типов и возможности новее 3.5.
- **Без внешних зависимостей.** Плагин использует только то, что уже есть в дистрибутиве: Python 3.5, PyQt5, numpy.
- **Изменения сцены и настроек** выполняем в главном потоке Qt через `app.callLater`.
- **Секреты в коде не храним.** Ключи LLM вводятся в настройках слайсера. Локальные данные плагина лежат в `data/` и не попадают в git.

## Pull request

- Опишите, что изменено и как проверить. Шаблон подскажет, что указать.
- Перед слиянием желательно, чтобы изменения посмотрел ещё один участник.

## Проверка

- Убедитесь, что файлы разбираются на Python 3.5, например интерпретатором из дистрибутива STE Slicer.
- Проверьте плагин в установленном STE Slicer 7.10: пункт меню, чат, нарезка.
